Getting started

Installation

Install the package from a clone of the repository. You can install only the core pipeline, or add the neural components that the default configuration uses.

Requirements

Requirement Details
Python 3.11 or newer. The reported results were produced with Python 3.11.9 on macOS (Apple Silicon).
Operating system macOS or Linux. The logger reads peak memory with Python's Unix-only resource module, so on Windows, run the pipeline inside WSL.
Memory About 20 GB at peak for the full dataset, developed on a 24 GB machine. The synthetic dataset and --sample runs fit on any laptop.
GPU Optional. The encoder and cross-encoder use Apple's GPU (MPS) or CUDA when available, and fall back to the CPU otherwise.
Disk and network The first run with embeddings downloads the 470 MB intfloat/multilingual-e5-small encoder from Hugging Face. Cached stage outputs for the full data take several GB in work/.

Core vs. embedding extras

git clone https://github.com/ShanmugaRamana/Entity-Resolver.git
cd Entity-Resolver
python -m venv venv && source venv/bin/activate

pip install -e .                  # core pipeline only
pip install -e ".[embed]"         # core + embeddings and cross-encoder (default configuration)
pip install -r requirements.txt   # the exact versions behind the reported results
Install Adds Use it for
pip install -e . polars, numpy, scipy, scikit-learn, rapidfuzz, lightgbm, anyascii Runs with --no-embed: blocking passes A–C, all features except the embedding cosine, and LightGBM.
pip install -e ".[embed]" torch, transformers, faiss-cpu The full default configuration: blocking pass D, the fine-tuned encoder and the cross-encoder.
pip install -r requirements-dev.txt pytest, ruff Running the tests and the linter (install the package first).

If you install only the core package, pass --no-embed to scripts/train.py. Without that flag, training tries to load torch and fails.

macOS and OpenMP

On macOS, LightGBM needs the OpenMP runtime, which does not ship with the system:

brew install libomp

If it is missing, training stops with "LightGBM could not load its OpenMP runtime. On macOS run: brew install libomp".

torch, transformers and FAISS each ship their own OpenMP runtime. Mixing those with LightGBM's in one process is fragile on macOS, so the pipeline only imports them inside separate worker processes. You don't need to configure anything for this.
