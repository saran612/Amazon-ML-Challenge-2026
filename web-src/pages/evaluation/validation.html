Validation protocol

All reported scores come from training data held out so that nothing was tuned on it. The protocol is also built so that the held-out businesses are no easier to match than real test data.

Avoiding leakage

  • Blocking runs over the full training data, so the held-out businesses face the same crowd of distractors and look-alikes as every other business.
  • A query counts as a validation query if its true owner or any of its candidates is a held-out S1 record. The matcher never trains on such a query, so it cannot learn anything about held-out businesses through their competitors.
  • Supervised vocabulary and fine-tuning use only pairs whose S1 record is outside the validation set. This applies to the token variants and to the encoder.
  • Out-of-fold scores: stage 2 trains on out-of-fold stage-1 scores, and the cross-encoder's training pairs are selected with them, never with in-sample scores.
