Error analysis

Every training run ends with an error analysis on half B. It shows where the remaining points are lost and what fixing each part would be worth.

Every false positive (a wrongly matched record) and every false negative (a missed true match) is tagged with the slices it belongs to. For each slice, the report gives the headroom: the gain in macro F0.5 if every error in that slice were fixed. That is an upper bound on what any improvement targeting the slice could achieve.

Slice Definition Headroom (macro F0.5)
Generic name Five or more S1 records share the core name
+0.009
Empty address The record has no address
+0.007
Blocking miss The true pair was never retrieved
+0.006
Non-Latin name The record's name contains non-ASCII characters listed in each report
Domain name The record's name is a web domain listed in each report
Trade name Core-name token-set similarity below 50 listed in each report

A slice's headroom only counts errors inside that slice, and slices overlap, so the headrooms do not add up. error_examples.tsv holds a random sample of the actual errors. Reading those examples is how the house-number problem was found:
