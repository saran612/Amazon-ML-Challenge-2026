Core concepts

Macro F0.5 scoring

Results are scored with macro F0.5: F0.5 is computed separately for each S1 record, then averaged over all S1 records.

For one S1 record, with tp correct predictions, n_pred predictions and n_true true matches:

precision P = tp / n_predrecall R = tp / n_true
F0.5 = 1.25 · P · R / (0.25 · P + R) = 1.25 · tp / (0.25 · n_true + n_pred)

Worked example: predict S2-00047, S2-00193, S3-00812 when the truth is S2-00047, S3-00812. Then P = 2/3, R = 1, and F0.5 = 0.714. Training checks this example before it starts, and scripts/score.py --self-test reproduces it.

Why precision counts double

F0.5 weights precision twice as much as recall, so a wrong merge costs more than a missed match. For an S1 record with 4 true matches:

Prediction Picture tp n_pred F0.5
3 correct, 1 missed 3 3 0.94
All 4 correct, plus 1 wrong × 4 5 0.83
correct match missed match ×wrong match

Because the score is averaged per S1 record, the best set of matches depends on each record's own probabilities. That is why the decision layer chooses a set for each S1 record instead of applying one global threshold.

Businesses with no match

An S1 record with no true match (a "singleton") is still scored:

  • An empty prediction scores 1.0.
  • Any prediction at all scores 0.0.

An S1 record that does have matches but gets an empty prediction scores 0.0, as does a non-empty prediction with no correct ids. Because every singleton is worth a full point when it is left empty, the decision layer explicitly compares the chance of "no match" against every possible set of matches.
