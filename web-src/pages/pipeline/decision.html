Pipeline

Decision layer

The decision layer turns pair probabilities into the final answer: one set of matched records for each S1 record. It is implemented in er/decide.py.

Assigning an owner

Each S2/S3 record can belong to at most one S1 record, so it is first assigned to its single most probable candidate. The other candidates are dropped. This is what makes conflicting merges impossible.

Choosing the set per business

Each S1 record now has a list of assigned records, each with a probability p. Records below t_assign are dropped. The rest are sorted by probability, and the layer keeps the top k records, choosing k to maximize expected F0.5. Expected F0.5 is approximated with expected counts:

E[F0.5 | top k] ≈ 1.25 · (p₁ + … + p_k) / ( 0.25 · (Σ p_all + miss_mass) + k )
P(no match) = Π (1 − pᵢ)→ choose the empty set if it beats every prefix

miss_mass accounts for true matches that blocking or assignment never delivered. Two parameters are tuned on half A: t_assign from {0.02, 0.05, 0.1, 0.15, 0.2, 0.3} and miss_mass from {0, 0.1, 0.25, 0.5}. A single global threshold (0.2 to 0.9 in steps of 0.025) is tuned as well, and the method that scores better on half A is used.

Consistency step

The records of one business should all end up with the same S1 record. The optional consistency step looks for records that are confidently matched (p ≥ 0.5) to an S1 record, called anchors. It then raises the probability of other candidates of that S1 record that are near duplicates of an anchor:

p'(q, s) = max( p(q, s), λ · p(anchor, s) · sim(q, anchor) )if sim ≥ sim_min

Here sim is the token-set similarity of the names, averaged with that of the addresses when both records have one. λ is chosen from {0, 0.5, 0.75, 1} and sim_min from {0.7, 0.85}, and λ = 0 means off. So far, every run has chosen "off".
