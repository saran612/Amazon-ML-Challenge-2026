Pipeline

Matcher

Features become a calibrated match probability in three steps: two LightGBM stages, isotonic calibration, and a cross-encoder for the pairs that are hardest to call.

Two-stage LightGBM

Stage 1 scores each pair on its own. It is a binary LightGBM model (255 leaves, learning rate 0.05, at least 200 rows per leaf, 80% feature and bagging fractions, L2 regularization 1.0). It trains with up to 2,000 rounds and stops early after 100 rounds without improvement. Training uses 3 folds grouped by S1 record, so all records of one business fall in the same fold. Every training row therefore gets an out-of-fold score from a model that never saw it. At prediction time, the three fold models are averaged.

Stage 2 answers a question stage 1 cannot: does this query have two plausible owners? Its inputs are the 24 most important base features from stage 1, plus six context features computed from the stage-1 scores of the query's candidates:

p1p1_rankp1_otherp1_marginp1_n_hip1_sum

These are the score, its rank, the best other candidate's score, the margin to it, the number of candidates above 0.5, and the sum of scores. Stage 2 trains on the out-of-fold scores, so it never learns from overconfident in-sample scores. It stops early on a 10% holdout of groups.

Training uses up to 30M candidate pairs from queries that touch no validation record. To fit in memory, the feature matrix is written to a memory-mapped file and binned once. Every fold then uses subsets of that one binned dataset, without copying it.

Calibration

The decision layer computes expected F0.5 from probabilities, so the scores have to be real probabilities. Isotonic regression, fitted on validation half A, maps the stage-2 score to a calibrated probability.

Cross-encoder

A cross-encoder reads both records together as name | address text, so it can catch typos and transliterations that pairwise features miss. It is too expensive to run on every pair, so it only re-scores the uncertain band:

  • Model: multilingual-e5-small with a classification head, trained with a binary cross-entropy loss (batch 64, learning rate 3e-5, up to 96 tokens).
  • Training pairs: up to 300k training pairs whose stage-1 out-of-fold score is between 0.02 and 0.98, the ones LightGBM found hard.
  • Applied to: validation and test pairs whose calibrated probability is between 0.02 and 0.98, about 0.7% of all pairs.
  • Blending: the two scores are combined in logit space, with a weight w for LightGBM:
p' = σ( w · logit(p_lightgbm) + (1 − w) · logit(p_cross_encoder) )
w ∈ {1.0, 0.75, 0.5, 0.25}

The weight is tuned on half A, and w = 1.0 switches the cross-encoder off. In the reported run it chose w = 0.5, which added +0.003 macro F0.5.
