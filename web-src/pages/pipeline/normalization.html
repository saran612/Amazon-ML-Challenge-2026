Pipeline

Normalization

The first step handles characters only. Nothing here knows any words: every word-level rule is learned later, from the data (see Learned vocabulary).

For every record, er/normalize.py:

  1. Keeps the original-script name, with whitespace collapsed, for the multilingual encoder. It also flags names that contain non-ASCII characters.
  2. Transliterates non-ASCII text to ASCII, then lower-cases it.
  3. Strips punctuation from the ends of names (-- Holloway Peak → holloway peak), and replaces all other punctuation with spaces.
  4. Detects domain-style names.
  5. Splits addresses on commas into segments, cleans each one, and separates digits from letters.

Transliteration

Non-ASCII strings go through anyascii, an offline Unicode-to-ASCII table covering every script. The order of operations matters here. The usual approach to accents is to decompose characters and drop the combining marks, but Indic vowel signs are combining marks too, so that approach deletes them. anyascii therefore runs first, before any accent handling, and a unit test checks that a Devanagari name keeps its vowels.

Transliteration helps character-level matching, but it cannot make two scripts agree on spelling. For names that differ only in script, the name embeddings do the work.

Domain-style names

A name that ends in label.tld (a label of at least four characters, then a 2–6 letter top-level domain) is treated as a web domain. The top-level domain is dropped, and the record is flagged with is_domain, which the model sees as a feature. Domains have no spaces, so coastaltungsten and Coastal Tungsten LLC share few words but many character trigrams. Blocking pass A and several features compare names with the spaces removed for this reason.
