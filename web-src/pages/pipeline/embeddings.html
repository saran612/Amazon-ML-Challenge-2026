Name embeddings

Character n-grams of a transliteration cannot match a Devanagari name to its English counterpart. A multilingual encoder, fed the original script, can place the two close together.

The encoder

Setting Value
Model intfloat/multilingual-e5-small: 118M parameters, MIT licence
Input The original-script name, prefixed with query: (the e5 convention for symmetric similarity), truncated to 32 tokens
Output 384-dimensional mean-pooled vector, L2-normalized, stored as float16
Used for Blocking pass D (nearest neighbours) and the cos_embed feature

Each distinct name is embedded once, however many records use it. On the full data that is about 11M names, which takes around 35 minutes on an Apple M4 Pro GPU.

Contrastive fine-tuning

Before embedding, the encoder is fine-tuned on training matches:

  • Pairs: one (S1 name, matching S2/S3 name) pair per S1 record, up to 300k. Only S1 records outside the validation set are used, and pairs with identical strings are dropped because they teach nothing.
  • Loss: symmetric InfoNCE with in-batch negatives (batch 128, temperature 0.05). Using one pair per S1 record means two members of a batch rarely belong to the same business, so few "negatives" are actually matches.
  • Schedule: AdamW with learning rate 2e-5, a 10% linear warm-up, then linear decay.

Use --no-finetune to embed with the pretrained weights, or --embed-model to swap in another encoder (a Hugging Face name or a local path).
