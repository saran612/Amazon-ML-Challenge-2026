Pipeline

Blocking

Comparing every record with every S1 record is impossible at this scale. Blocking keeps a short list of candidate S1 records for each query while losing as few true pairs as possible.

Blocking runs separately for each country, and only same-country records are compared. For each country, TF-IDF matrices (sublinear term frequency) are fitted on that country's records in the files being processed.

The four passes

Pass Search on Top k Catches
A Character 3-gram TF-IDF of the core name, spaces removed 10 Typos, reordered words, domain names
B Word TF-IDF of the address 8 Trade names: a different name at the same address
C Word TF-IDF of core name + address 10 Generic names that only the address tells apart
D Nearest names in the embedding space (FAISS) 15 The same name written in another script

Passes A–C are sparse top-k searches, run in parallel over chunks of queries. For these searches only, columns that appear in more than 1% of a country's S1 records (with a floor of 200) are ignored: they carry little signal and account for most of the cost. Pass D uses an exact index for fewer than 20k S1 records, and an IVF index otherwise (about 4√n lists, 16 probed).

Ranking and capping

The four passes' results are combined, and each pair gets a combined score:

comb = 0.4 · cos_char + 0.4 · cos_joint + 0.2 · cos_addr

A query keeps its 16 best candidates by comb, plus anything ranked in the top 3 of any single pass. The second rule protects a pass that is the only one to find a match, such as an embedding hit on a name in another script. For every pair, blocking also records its rank in each pass, its comb rank, the margin to the query's best other candidate, and the number of candidates. These all become features.
