Features

Each candidate pair gets 77 features, defined in er/features.py. A value that cannot be computed, such as an address comparison when one side has no address, is set to −1 so that the model can tell "missing" apart from "different".

There is deliberately no country feature. The model has to learn rules that transfer, so it can be applied to a country it has never seen.

Blocking context

These features come straight from blocking: the four TF-IDF cosines (character, name words, address, joint) and the embedding cosine; the combined score, its rank and its margin to the query's best other candidate; the rank in each pass (99 when a pass did not find the pair); and the number of candidates. Two IDF features measure the rarest word the two records share, in the name and in the address. Sharing "Holloway" means much more than sharing "Services".

Name and address

  • Fuzzy scores from RapidFuzz: ratio, token-set, token-sort and partial ratio on the full name; ratio, token-set and Jaro-Winkler on the core name; ratio and partial ratio with spaces removed; the ratio of the consonant skeletons; and token scores on the full address, the places and the street part.
  • Soft token matches, in both directions: the share of one record's tokens that have an exact, abbreviation or close-spelling (Jaro-Winkler ≥ 0.85) partner in the other record. This is computed for the core name and for the street.
  • Place agreement: the share of places that are equal or linked, in both directions.
  • Flags and shape: first token equal, the query's source (S2 or S3), non-Latin script, domain names, empty addresses, token counts, the length ratio, and the numbers of house numbers and places.
  • Rarity: core_cnt and local_cnt on both sides, and how many of the query's candidates share this S1 record's core name.

House numbers

House numbers separate two kinds of mismatch that look alike. A true match can have noise (305 H Street vs 304 H Street), while a different business with the same name can sit a few doors away (2026 vs 2005 N Dakota Avenue). The features include whether any numbers are shared exactly or partly, the closest pair of numbers, whether the first numbers are equal, and four distances between the first numbers: absolute (log-scaled), relative, off by ≤ 2, and digit edit distance. The relative difference became the third most important feature.

Siblings and competitors

Siblings. The strong siblings of an S1 record are the queries whose best blocking candidate it is, with comb ≥ 0.5 (at most 10 per S1 record, best first). A true match usually resembles the business's other records even when it differs from the S1 record itself. Six features describe how a query compares with its candidate's siblings: their count, the best name, address and joint similarity, and how often their house numbers agree or are close. Siblings are found from blocking output only, without labels, so they are built the same way on training and test data.

Competitors. These features look at the other candidates of the same query. Is this S1 record the best address match among all of them? Among those with the same core name? By how much? And how much further away is its house number than the closest same-name competitor's? These features settle cases where several businesses with the same name compete for one record.
