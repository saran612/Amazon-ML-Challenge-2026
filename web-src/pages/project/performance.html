Peak memory stays around 20 GB for about 200M candidate pairs. The techniques that keep it there:

  • Candidate pairs are written to disk per country and streamed in chunks that never split a query's candidates. Only the query column stays in memory.
  • The training feature matrix is a memory-mapped file, binned once for all LightGBM folds.
  • The pair table uses compact types, at about 45 bytes per pair.

On a smaller machine

  • Start with --sample to measure how long each stage takes.
  • Lower --jobs. Each worker process holds its own share of the data.
  • Lower feature_chunk and max_train_pairs in Config.
